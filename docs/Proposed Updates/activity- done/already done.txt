1. Why This Was Done
DiaTwin previously modelled two terms in its daily "bank-balance" baseline:
cumulativeNetBaseline = cumulativeMealEffect + cumulativeInsulinEffect
Physical activity was handled only indirectly — via activity_coefficients that adjusted insulin sensitivity constants — but produced no direct BG-lowering signal in the cumulative model. This meant the estimated BG never reflected the acute glucose drop from a run or cycle, and the post-exercise period of heightened insulin sensitivity was invisible to the frontend.
The update adds a physiologically grounded third term:
cumulativeNetBaseline = cumulativeMealEffect + cumulativeInsulinEffect + cumulativeActivityEffect
The model used is the Dalla Man / Breton HR-ODE system [1][2], which separates acute and delayed exercise effects through three coupled differential equations integrated with 1-minute Euler steps.

2. Physiological Model Summary
State Variables
VariableRoleTime ConstantYFiltered HR above baseline — proxy for energy expenditure / muscle activationτ_HR = 5 minZAcute IIRd signal — insulin-independent glucose uptake via GLUT4 during contractionτ_Z = 10 min (fast decay post-exercise)WCumulative load ∫Y dt — drives post-exercise GLUT4 upregulationτ_W = 90 min (slow decay)
Bimodal Output

Z → cumulative_activity_effect: Signed mg/dL drop during and shortly after exercise (acute IIRd).
W → sensitivity_multiplier: Post-exercise ISF/CR boost that persists for up to 8 hours (IDRd / GLUT4 upregulation).

ODE Equations (Euler, dt = 1 min)
dY/dt = (HRabove / τ_HR) − (Y / τ_HR)
dZ/dt = (1 − Z)    if in-exercise window and Y > a·HRbase
      = −Z / τ_Z   otherwise (recovery)
dW/dt = Y          during exercise
      = −W / τ_W   in recovery
HR Input Priority

Wearable HR trace [{t_min, hr_bpm}] — from Garmin / Fitbit / Apple Watch.
Synthetic trace built from categorical intensity (light / moderate / vigorous) when no wearable is connected — fully supported, physiologically plausible.

Population Constants (calibrated from Romeres et al. 2021 [3])
pythonHR_MODEL = {
    "tau_HR": 5.0, "tau_Z": 10.0, "tau_W": 90.0,
    "a": 0.05,           # onset threshold
    "alpha": 0.0008,     # W·Z → sensitivity boost scaling
    "max_sensitivity_boost": 0.60,    # 60 % hard cap
    "acute_rate_per_min": 0.15,       # mg/dL/min at Z = 1
    "dt": 1.0,
    "hr_max_pop": 190.0, "hr_base_pop": 70.0,
}

Key design decisions correctly implemented:

Sedentary records (level ≤ −1) return None from normalization — they affect insulin coefficients separately, not the direct BG drop.
bg_direction field controls sign: −1 for aerobic (default), +1 for stress/anaerobic.
Allometric weight scaling: drop × (70 / weight_kg)^0.25.
sensitivity_multiplier uses max() across sessions — GLUT4 receptors don't stack additively.
8-hour cutoff on W: sessions older than 8 h (≈ 5 × τ_W) contribute < 1 % and are skipped.

6. Issues Found & Resolved
✅ Issue 1 — Broken MealType interface (VERIFIED FIXED)
The export interface MealType { declaration is correctly present at line 140 of shared-constants.ts, immediately after the closing } of HrModel. tsc --noEmit passes on this file.
✅ Issue 2 — AOB card disappears during post-exercise W window (FIXED)
Root cause: Three related conditions in ActiveEffectsDisplay.tsx only checked cumulativeActivityEffect !== 0. After the acute Z-integral decays to 0, the card vanished even though sensitivity_multiplier was still > 1.0 (W window persists for up to 8 hours).
Fixes applied to ActiveEffectsDisplay.tsx:

Line 1230 — card visibility: (activeSessions > 0 || cumulativeActivityEffect !== 0) → added || sensitivityMultiplier > 1.0
Line 1006 — formula strip: cumulativeActivityEffect !== 0 → (cumulativeActivityEffect !== 0 || sensitivityMultiplier > 1.0)
Lines 1021–1026 — formula label ternary: both inner conditions updated to match the same || sensitivityMultiplier > 1.0 logic

✅ Issue 3 — Silent API failure hides card with no diagnostic output (FIXED)
Root cause: Both .catch(() => null) blocks for the activityPD fetch swallowed errors silently, making it impossible to distinguish "no exercise today" from "endpoint 404" or "auth error" in the debugger.
Fixes applied:

ActiveEffectsDisplay.tsx line 271: .catch((err) => { console.warn('[ActiveEffectsDisplay] ⚠️ activityPD fetch failed — card hidden:', err); return null; })
useActiveEffects.ts line 411: .catch((err) => { console.warn('[useActiveEffects] ⚠️ activityPD fetch failed — activity effect will be 0:', err); return null; })

✅ Issue 4 — PatientConstants TypeScript interface missing ODE fields (FIXED)
Root cause: mobile/types/constants.types.ts was not updated alongside backend/constants.py v4.4. The PatientConstants interface was missing weight_kg, hr_base, hr_max, carb_to_bg_ratio, baseline_mode, and circadian_profile. TypeScript would throw "property does not exist" errors in calculateTotalCumulativeEffects and the ODE utility, and getConstant('weight_kg') would silently return undefined, causing the ODE to use the population default 70 kg for all patients.
Fix applied to mobile/types/constants.types.ts: all 6 fields added as optional (?) for backward compatibility with pre-v4.4 patient records in MongoDB.
✅ Issue 5 — Dual ActivityContribution definition (ACCEPTABLE, UNCHANGED)
Both definitions are structurally identical; TypeScript's structural typing makes them interchangeable at compile time with no runtime impact.
